# LuminaX 阶段二：统一工作台设计规格

**日期：** 2026-08-11  
**状态：** 已完成产品讨论，待实施计划  
**范围：** 完整工作台体验  
**前置条件：** 阶段一工作台上下文与角色模板基础已经合入 `main`

## 1. 背景

LuminaX 当前前台由聊天、看板和报表三个互相切换的页面模式组成。该结构能够完成 POC 演示，但数据分析与 AI 决策过程被拆开，角色差异和权限上下文也没有完整投射到界面。

本阶段将前台升级为“统一工作台 + 角色模板 + 权限驱动”的双核心体验：经营数据与 AI 助手在同一工作上下文中协作，同时保持现有登录、数据、聊天、报表和 Agent API 兼容。

## 2. 目标

- 建立统一的经营工作台，不再以互斥整页模式分隔聊天、看板和报表。
- 在桌面端同时呈现经营数据和 AI 助手。
- 接入 `/api/workbench/context`，让角色模板控制默认体验，让权限控制实际可见范围。
- 支持区域经理、CEO/CFO/COO 类管理者和默认角色使用同一套组件。
- 完整支持桌面、平板和最小 360px 宽度的移动端。
- 复用现有数据、图表、报表、流式会话和 AI 意图联动逻辑。

## 3. 非目标

- 不修改数据库表结构、固定 SQL 指标计算或指标注册流程。
- 不修改现有 Agent 编排和 `/api/chat` 流式协议。
- 不新增自由拖拽布局、用户自定义看板或持久化个人布局。
- 不新增业务 API；仅使用阶段一已经提供的 `/api/workbench/context`。
- 不在本阶段重写指标计算引擎、图表引擎或报表生成器。
- 不以角色模板代替服务端权限校验。

## 4. 总体架构

```text
登录用户
  -> LuminaXApp（初始化与编排）
    -> useWorkbenchContext -> /api/workbench/context
    -> useLuminaXController -> 现有数据、图表和报表能力
    -> useChatStream -> 现有 AI 流式会话能力
    -> WorkbenchShell
      -> WorkbenchHeader
      -> ScopeBar
      -> InsightCanvas
      -> AssistantPanel
```

依赖方向必须保持单向：服务端权限上下文 -> 工作台上下文 Hook -> 页面编排 -> 展示组件。展示组件不得自行扩大数据范围，也不得根据角色名称推导数据权限。

## 5. 组件边界

### 5.1 LuminaXApp

`LuminaXApp` 是工作台组合根，负责：

- 初始化工作台上下文、经营数据和聊天会话。
- 将筛选状态、视图状态、授权选项和事件处理器传给子组件。
- 将 AI 返回的结构化意图交给控制器处理。
- 呈现工作台级加载、授权失败和重试状态。

`LuminaXApp` 不直接渲染指标卡、图表、聊天消息或具体筛选控件。

### 5.2 WorkbenchShell

`WorkbenchShell` 只负责布局：

- 桌面端使用经营画布与 AI 助手并列的双栏布局。
- 平板端保留经营画布主区，并允许助手面板收窄或展开。
- 移动端使用“经营数据 / 分析决策”分段切换。
- 在视图切换时保留筛选、图表、报表和聊天状态。

### 5.3 WorkbenchHeader

`WorkbenchHeader` 展示品牌、当前用户、角色模板标识、退出操作和管理后台入口。管理后台入口只在 `context.canAccessAdmin` 为真时显示，不能直接根据客户端用户角色判断。

### 5.4 ScopeBar

`ScopeBar` 统一承载：

- 时间范围。
- 主门店或汇总范围。
- 对比门店。
- 可用指标。

候选项必须来自工作台上下文与现有数据的交集。筛选变化通过控制器驱动数据画布更新，并成为后续 AI 请求的当前分析上下文。

### 5.5 InsightCanvas

`InsightCanvas` 承载三个内部视图：

1. **经营概览：** 指标卡、趋势图、门店对比和异常提示。
2. **分析视图：** AI 触发的归因结果和经营建议。
3. **报表视图：** 复用现有报表 HTML 与预览能力。

三个视图共享同一筛选状态。视图切换不能重置当前门店、时间、对比范围或聊天会话。

### 5.6 AssistantPanel

`AssistantPanel` 复用现有流式会话协议，负责：

- 展示历史消息、流式响应、失败状态和重试入口。
- 提交自然语言问题。
- 承载归因分析、经营建议和周报指令。
- 将结构化意图传给页面编排层，而不是直接修改全局状态。

## 6. 工作台上下文契约

本阶段复用阶段一稳定类型：

```ts
interface WorkbenchContext {
  templateId: "regional_manager" | "default";
  availableStoreIds: string[];
  availableMetricCodes: string[];
  availableIntents: WorkbenchIntent[];
  canAccessAdmin: boolean;
}
```

新增 `useWorkbenchContext` 作为客户端读取边界，至少暴露：

- `context`：成功规范化的上下文。
- `isLoading`：初始化状态。
- `error`：不包含敏感服务端细节的错误。
- `reload`：重新读取上下文。

接口返回未知模板时回退到 `default`。接口失败时不得假定全量门店或全量指标权限。

## 7. 角色模板行为

所有模板使用同一套工作台组件。模板只控制默认视图、内容顺序、视觉强调、推荐问题和空状态文案。

### 7.1 区域经理模板

- 默认范围：用户有权访问的辖区门店。
- 优先内容：门店对比、异常门店、目标完成情况。
- 优先 AI 能力：异常归因、经营建议、周报。

### 7.2 默认模板

- 默认范围：用户有权访问的全部范围。
- 优先内容：通用核心指标、趋势和风险提示。
- 优先 AI 能力：数据问答、经营分析和报表。
- CEO、CFO、COO 及未知角色在没有专属模板时使用该模板。

角色模板不得授予门店、指标、表、字段或字段值权限。

## 8. 数据与交互流程

1. 登录成功后，客户端读取 `/api/workbench/context`。
2. 上下文返回模板、门店、指标、意图和后台访问能力。
3. `ScopeBar` 只生成授权范围内的选项。
4. 控制器使用当前筛选调用现有数据能力。
5. `InsightCanvas` 展示指标、图表、异常或报表。
6. AI 请求携带当前分析范围所需的现有上下文。
7. AI 返回的门店、日期或视图意图先交给控制器处理。
8. 门店和指标意图必须与 `WorkbenchContext` 取交集后才能应用。
9. 服务端继续对每次数据和 AI 请求执行最终授权。

## 9. 响应式设计

### 9.1 桌面端

- 主区域约占可用宽度的 68%，AI 助手约占 32%。
- 两个核心区域同时可见，助手面板保持稳定宽度约束。
- `ScopeBar` 位于数据画布上方，并允许控件按内容换行。

### 9.2 平板端

- 经营画布保持主要空间。
- AI 助手可以收窄或通过明确操作展开。
- 图表由双列降为单列或适配后的紧凑双列。

### 9.3 移动端

- 使用“经营数据 / 分析决策”分段控件切换核心区域。
- 不强制压缩桌面双栏。
- 切换时保留筛选、滚动前的业务状态和会话内容。
- 复杂图表或表格可以局部横向滚动。
- 从 360px 起不得出现关键文字截断、控件重叠或操作不可达。

## 10. 视觉规范

- 页面以白色和浅灰为基础工作面。
- 主要文字使用黑色或高对比深灰。
- LuminaX 黄色 `#FFE600` 用于品牌、选中状态和主要操作，不作为大面积背景。
- 红、绿、蓝只用于风险、健康和信息状态。
- 页面区块保持平整紧凑；卡片仅用于指标、独立重复项和明确框定的工具。
- 卡片圆角不超过 8px，除非现有设计令牌已有更严格约束。
- 使用项目现有图标库中的标准图标，并为不熟悉的图标操作提供工具提示。
- 控件和图表使用稳定尺寸约束，加载和内容变化不得造成明显布局跳动。

## 11. 异常与降级

- **上下文加载失败：** 展示工作台级错误和重试操作，不请求未授权业务数据。
- **未知模板：** 回退到 `default`。
- **无可用门店或指标：** 展示空状态，不扩大查询范围。
- **单个图表失败：** 隔离在对应区域，其他数据和助手继续可用。
- **AI 请求失败：** 保留当前数据与对话，允许重新提交。
- **报表生成失败：** 保持当前视图，展示失败信息和重试入口。
- **会话中权限变化：** 后续请求服从服务端最新权限，客户端重新加载上下文。

## 12. 兼容策略

- 保留 `/`、`/login`、`/admin` 和现有管理后台子路由。
- 保留 `/api/data`、`/api/chat`、报表接口和认证接口的协议。
- 现有图表配置、报表 HTML、流式消息和意图元数据通过适配层继续使用。
- 新组件稳定后再移除不再引用的旧布局组件。
- 不修改 MySQL 与 SQL Server 数据源接口。

## 13. 测试与验收

测试集中覆盖高风险边界，避免为纯视觉细节增加大量低价值测试。

### 13.1 自动化测试

- 工作台上下文加载、错误状态和默认模板回退。
- 门店、指标和管理入口受权限上下文限制。
- AI 意图不能切换到无权门店或无权指标。
- 桌面双栏与移动端分段切换的关键状态行为。
- 现有测试集继续通过。

### 13.2 浏览器烟雾测试

- 登录后进入统一工作台。
- 查看经营概览并切换授权门店和日期。
- 发起 AI 分析并确认数据视图保持可用。
- 打开归因或报表视图。
- 在桌面和 360px 移动视口检查布局、溢出、遮挡和关键操作。

## 14. 完成定义

- `/` 已使用统一工作台，不存在聊天、看板、报表互斥整页的主体验。
- 桌面端经营数据和 AI 助手同时可见。
- 移动端通过分段控件完整访问两类能力。
- 角色模板能改变默认体验，但不能改变权限。
- 无权限门店、指标和管理入口不会出现在工作台中。
- AI 意图经过权限交集后才应用到界面。
- 现有核心 API、固定 SQL 指标和 Agent 链路保持兼容。
- 精简自动化测试及桌面、移动端烟雾检查通过。

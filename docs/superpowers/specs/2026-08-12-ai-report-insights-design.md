# LuminaX 周报 AI 洞察设计

**日期：** 2026-08-12  
**范围：** 仅优化周报中的“经营趋势总结”和“需关注信息”

## 1. 目标

在不改变现有指标计算、数据范围、图表和周报其他内容的前提下，使用 DeepSeek 基于已计算的周报聚合数据生成更专业的经营趋势总结与关注事项。模型不得计算、修改或虚构指标。

## 2. 生成策略

- 每份周报只调用一次 DeepSeek，同时生成两个内容区块，保证口径一致。
- 输入使用完整的 `WeeklyReportData` 聚合信息，包括销售与目标、订单、客单价、退款、促销、日趋势、门店排名、渠道、品类、时段和异常日期；不传原始交易明细。
- 经营趋势总结输出 4–6 条有明确数据依据的判断。
- 需关注信息最多 5 条，每条包含风险等级、标题、判断依据和可执行建议。
- 无法由数据直接支持的因果判断必须写成“建议进一步核查”，不得表述为确定事实。

## 3. 模型契约

新增独立的周报洞察生成器，依赖现有 `AgentModel` 接口。运行时使用独立的 `DeepSeekChatModel` 实例，模型名称优先读取 `DEEPSEEK_REPORT_MODEL`，未配置时回退到 `DEEPSEEK_MODEL`。

模型必须返回严格 JSON：

```json
{
  "trendSummary": ["经营判断"],
  "attentionItems": [
    {
      "severity": "high | medium | low | positive",
      "title": "关注事项标题",
      "evidence": "仅引用输入数据的依据",
      "action": "具体行动建议"
    }
  ]
}
```

服务端负责解析、字段数量限制、空值清理和 HTML 转义。模型输出不直接作为 HTML 注入页面。

## 4. 数据流与接口

1. 周报引擎先按现有逻辑构建 `WeeklyReportData`，SQL/本地计算结果仍是唯一数值事实来源。
2. 周报洞察生成器将聚合数据序列化后调用 DeepSeek。
3. 有效模型结果传给 HTML 模板，仅替换“经营趋势总结”和“需关注信息”。
4. 模型未配置、超时、请求失败、JSON 非法或内容不满足契约时，静默调用现有 `buildReportSummaryParts` 和 `buildReportAlerts`。
5. `generateWeeklyReportHTML` 升级为异步函数；调用方等待生成完成后再展示周报。其他报告数据构建与渲染接口保持兼容。

## 5. 边界与安全

- DeepSeek 不获得数据库凭据、用户权限策略、系统 Prompt、原始明细或其他 Agent 记忆。
- 模型只负责文字解释，不改变 `WeeklyReportData`、图表数据或 KPI。
- 所有模型文本在进入 HTML 前转义，防止脚本或标签注入。
- 失败回退不向最终用户展示模型错误，服务端仅记录不包含敏感数据的诊断信息。

## 6. 测试与验收

- 使用 Fake AgentModel 验证单次调用、输入包含关键聚合数据、输出契约解析和数量限制。
- 验证模型返回空值、异常或非法 JSON 时，HTML 与现有规则内容一致。
- 验证模型文本被 HTML 转义，且不能改变周报中的 KPI 和图表数据。
- 验证指定门店与日期范围仍贯穿数据构建、AI 洞察和最终周报。
- 只运行周报相关测试、类型检查和一次生产构建；不扩大无关测试范围。

## 7. 非目标

- 不修改 SQL 指标计算、图表、门店排名和其他周报区块。
- 不新增管理后台配置页面、独立 Report Agent、RAG 或多轮记忆。
- 不调整治理、业务和归因 Agent 的职责。
